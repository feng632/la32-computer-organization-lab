# ex8 回归结果与收益归因（2026-10-31）

## 三次运行的条件

| 运行 | RTL | 预测器 | 镜像 | 结果 |
|---|---|---|---|---|
| A. 旧基线 | 10-30 版本（预测器接入前、B 改动前） | 无 | ex8 | 47/47，`$finish` **1385245 ns** |
| B. 当前 RTL，BP=0 | 10-31 20:20 版本 | 关闭 | ex8 | 47/47，`$finish` **1383245 ns** |
| C. 当前 RTL，BP=1 | 10-31 20:20 版本 | 开启 | ex8 | 47/47，`$finish` **1383155 ns** |

镜像确认：三次都是 47 项检测点（ex9 是 58 项），`inst_ram.mif` 为 ex8 版本。
B 与 C 的编译日志中 `Compiling module xil_defaultlib.mycpu_top` 分别为无参数后缀
（取默认 `BP_ENABLE=1'b0`）与 `(BP_ENABLE=1'b1)`，证明宏切换真实生效。

## 功能结论

**B 与 C 都 47/47 通过，0 条 `Error!!!`，`Test end! PASS`。**
预测器接入后 ex8 功能未被改坏，这条独立成立。

## 收益归因

| 对比 | 差值 | 归因 |
|---|---|---|
| A → B（旧基线 → 当前 RTL BP=0） | **−2000 ns（200 拍）** | B 的语义改动，与预测器无关 |
| B → C（BP=0 → BP=1） | **−90 ns（9 拍）** | 预测器 |
| A → C | −2090 ns | 两者之和 |

逐项区间比对（数据见 `ex8-three-way-2026-10-31.csv`）：

- A → B：**46 个区间里 45 个完全相同**，只有 `#18→#19` 一处少 200 拍，此后一路保持。
- B → C：**46 个区间里 45 个完全相同**，只有 `#46→#47` 一处少 9 拍。

也就是说：

1. 那 200 拍是 B 的改动带来的**一次性**收益，集中在单一区间内。
2. 预测器在 ex8 上的全部贡献只有 **9 拍（90 ns，0.0065%）**，出现在最后一个区间。
3. 除这两处外，ex8 的其余执行段对"有没有预测器"完全不敏感。

## 结论

**预测器在 ex8 上几乎零收益。** 这与 P3 的结论一致：收益来自 BTB 命中的时间局部性，
而 ex8 的分支绝大多数只执行一次或循环次数极少，没有可供命中的重复。

**因此不能用 ex8 的 `$finish` 变化来证明预测器有效。** 早前把 A→C 的 2090 ns 整体
当作"预测器生效"是错的，其中 2000 ns 属于 B 的改动。

对比之下，ex9 的 BP0/BP1 两次都是当前 RTL、同期运行（2039015 → 2035305，−3710 ns），
那是干净的预测器收益，可以引用。

## 勘误：上一版本文档的一处错误

本文档初版（21:20 前后）称"`#41→#42` 区间多花 200 拍，不符合 2 级流水常识"。

不存在的异常已从结论中删除，`ex8-bp0-vs-bp1-2026-10-31.csv` 一并作废，
