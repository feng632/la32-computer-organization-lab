## 2. 第一版预测器算法（A）

采用 64 项直接映射的目标地址表 BTB（Branch Target Buffer），每项含：

| 字段 | 位宽 | 含义 |
|---|---:|---|
| valid | 1 | 本项有记录 |
| tag | 24 | 完整区分同索引的地址，取 PC[31:8] |
| target | 32 | 最近一次计算出的跳转目标，保留低两位 |
| is_cond | 1 | 条件分支为 1，b/bl/jirl 为 0 |
| state | 2 | 条件分支的两位饱和状态 |

索引取 PC[7:2]。总逻辑存储量为 64×60=3840 bit，不要求推断成 BRAM；最终资源以综合报告为准。

1. 组合查表，时钟上升沿更新。复位同步高有效，清所有 valid；其余字段也置零，方便仿真，不输出 X/Z。
2. `query_hit = enable && !reset && query_pc[1:0]==0 && valid[index] && tag_match`。
3. `predict_taken = query_hit && (!is_cond || state[1])`。
4. `predict_target = query_hit ? target : 32'b0`；只有 predict_taken=1 时将其作为下一地址，否则用 query_pc+4。
5. 条件分支：00/01/10/11 分别为强不跳、弱不跳、弱跳、强跳；实际跳则饱和加一，否则饱和减一。
6. 新建、地址冲突替换或类别改变时，条件分支按本次结果初始化为 10（跳）或 01（不跳）；同地址同条件类别才沿用旧状态并加减。无条件跳转状态固定 11。
7. 每次有效分支更新都写目标，包括未采用的条件分支目标；条件分支目标是 PC+偏移，不能误写成 PC+4。b/bl/jirl 每次更新目标。
8. 非分支更新：只在对应索引 valid 且 tag 匹配时清 valid，不误删冲突的其他地址；其他字段可保持。这样可以清除残留的错误分支记录。
9. enable=0 或 reset=1 时不进行普通更新；reset 优先于更新。WB 冲刷不清表，保留历史。
10. 同一上升沿查询、更新同一项，IF 采样的是**更新前的组合输出**；不做更新旁路。更新后查询可能变化，已锁存的预测信息不变。

## 3. 固定接口表

全部使用现有 CPU 时钟、同步高有效 reset。enable 为构建时固定设置，禁止运行中切换。

### 3.1 预测器 branch_predictor 的端口

| 端口 | 方向 | 位宽 | 驱动者/时序 |
|---|---|---:|---|
| clk / reset | input | 1/1 | C 顶层 |
| enable | input | 1 | C 顶层参数 BP_ENABLE |
| query_pc | input | 32 | C/IF，本拍最终准备请求的 fetch_addr |
| query_hit | output | 1 | A，组合查询结果 |
| predict_taken | output | 1 | A，组合查询结果 |
| predict_target | output | 32 | A，组合查询结果 |
| bp_update_bus | input | 68 | B 产生，C 直接连接；valid 表示本上升沿更新一次 |

### 3.2 IF ↔ 顶层 ↔ 预测器（C）

IF 新增输出 `bp_query_pc[31:0]`，新增输入 `bp_query_hit`、`bp_predict_taken`、`bp_predict_target[31:0]`。由 C 在顶层连接至 A 对应端口。IF 不另行译码指令，也不窥视 A 的表内寄存器。

`mycpu_top` 增加参数 `BP_ENABLE=0`（默认关闭），只传给预测器 enable，外部引脚不变；性能构建明确设置 0 或 1。关闭时仍使用同一套纠正逻辑，只是所有预测均为顺序地址，**功能应与 ex9 一致，但不要求与旧 RTL 逐拍相同**。

### 3.3 IF → ID 的预测信息

新宏 `BP_META_WD=34`；端口名 `fs_to_ds_bp`，由 C/IF 输出、B/ID 输入，经 C 顶层连接。

| 字段 | 位段 | 含义 |
|---|---|---|
| hit | [33] | 该指令取指时查表命中，仅供测试统计 |
| taken | [32] | 该指令取指时实际采用了跳转预测 |
| next_pc | [31:0] | 该指令预测的后继地址；不跳时为该指令 PC+4 |

复用现有 `fs_to_ds_valid && ds_allowin && !pipe_flush` 锁存，与指令/PC/49 位异常信息同时进入 ID。没有独立 bp_valid。不得在 ID 实时重查预测器，否则阻塞或更新可能改变已经作出的预测。

### 3.4 ID → IF 的纠正

原 `BR_BUS_WD=33` 保持；拓展模式定义 `br_bus={bp_redirect_valid,bp_redirect_pc[31:0]}`。B 输出、C/IF 输入。IF 内旧变量 br_taken 应更名或明确按纠正含义使用，不能同时再驱动旧实际跳转事件。

这条总线只能使 IF 改路，**不能并入 pipe_flush**，否则会误取消 ID 当前正确的分支及更老指令。

### 3.5 ID → 预测器的学习结果

新宏 `BP_UPDATE_WD=68`；ID 新增输出 `bp_update_bus`，C 连至 A。

| 字段 | 位段 | 含义 |
|---|---|---|
| valid | [67] | 本周期是一条正常指令真正发射的事件 |
| is_branch | [66] | beq/bne/blt/bge/bltu/bgeu/b/bl/jirl 之一 |
| is_cond | [65] | 前六种条件分支之一；非分支置 0 |
| taken | [64] | 实际是否跳转；非分支置 0 |
| pc | [63:32] | 当前 ID 指令地址 |
| target | [31:0] | 分支计算目标，即使条件不满足也给分支目标；非分支置 0 |

valid=0 时整个 68 位输出零。正常非分支也发送有效更新，用于 A 的匹配失效处理。enable=0 时 A 忽略更新，ID 无须增加 enable 输入。

机器副本见 [branch-prediction-v1.json](branch-prediction-v1.json)。宏只由 B 修改，不能重复放到 A 的私有定义文件里。

## 4. B 的 ID 事件规则

以下是设计公式，需 B 实现为真实信号，不代表现有源码已有这些变量：

```text
id_fire      = ds_to_es_valid && es_allowin && !reset
normal_fire  = id_fire && !ds_exc[48] && !inst_ertn
actual_taken = is_branch && 使用已有比较结果和译码；此处为未加握手条件的真实方向
actual_next  = actual_taken ? actual_target : ds_pc + 4
bp_redirect_valid = normal_fire && (saved_prediction.next_pc != actual_next)
bp_redirect_pc    = bp_redirect_valid ? actual_next : 0
update.valid     = normal_fire
```

- ds_to_es_valid 已含 !pipe_flush；实现和审查时仍确认全局冲刷当拍 normal_fire=0。
- `ertn` 的改路只在 WB 生效，ID 不发普通纠正，也不训练；CSR/计数器正常发射时按非分支更新，已有排空条件不变。
- 中断覆盖当前指令时 ds_exc 有效，不纠正、不更新、不写当前指令原本的 CSR/寄存器任务；继续沿 ex9 异常通路到 WB。
- **对所有正常指令比较 next_pc**，不能只检查实际分支。否则表中残留的误预测可能让普通指令后错误跳走。
- 使用当前已有前递值与 hazard 判断。load-use、除法相关或 es_allowin=0 时，不重复学习、不提前改路。
- 纠正只取消年轻 IF 指令；ID 当前指令照常进入 EXE。bl/jirl 的链接寄存器写回及 PC+4 计算保持原有语义。
- 较老指令尚未在 WB 提交时允许 ID 训练。若之后较老指令异常，表内可能留下推测历史，但只是性能状态；所有架构副作用仍由现有异常/冲刷机制保护。不增加“训练等 WB”通路。

## 5. C 的同步指令 RAM 时序与优先级

### 5.1 查询与锁存，避免组合环

采用“本次查询在请求上升沿锁存，结果用于后续取指”的方案：

1. 用 IF **已保存**的预测后继、待处理异常目标或当前 ID 纠正目标，选择本拍 fetch_addr。
2. bp_query_pc=fetch_addr；查询结果不得反过来参与本拍 fetch_addr 的选择。
3. 本次正常 RAM 请求被接受的上升沿，同时保存 fs_pc=fetch_addr，以及 `{hit,taken,taken?target:fetch_addr+4}`。下一周期 RAM 返回的指令与这些信息对应。
4. 若生成 ADEF 标记而不读 RAM，同样锁存 PC，但预测信息强制 `{0,0,fetch_addr+4}`；不查询采用未对齐 PC 的表项。目标低两位不被擅自清零。
5. IF 向 ID 成功传输时传出这些寄存器，不能用此时查询输出替代。
6. ID 阻塞且 IF 已有有效指令时，不发新请求，PC/预测寄存器保持，指令 RAM 读口维持现有一拍同步读行为。

### 5.2 选路与有效位

优先级：reset > 当前 WB 的 pipe_flush > 已锁存的 WB 重定向目标 > ID 纠正 > 普通预测后继。

- reset：IF 无效、重定向缓存清空，普通取指起点明确设为 0x1c000000；不能使用复位伪 PC 的预测值推导错误起点。
- WB 冲刷当拍：不发 RAM 请求、不发 ADEF 标记、不送旧 IF 指令到 ID；清 fs_valid，锁存 WB 目标。下一可取指拍消费它。
- 已锁存 WB 目标在成功 RAM 请求或生成 ADEF 标记时消费一次；未消费时不能被旧普通路径覆盖。
- ID 纠正当拍：禁止旧 IF 指令送进 ID，**允许直接向正确目标发本拍请求**。此时 normal_fire 保证 es_allowin=1 且 ID 可接收，因而已有 IF 允许条件能发请求。请求成功后 fs_valid 应反映新目标请求，不能被“纠正就清零”覆盖丢掉新响应。
- ID 纠正与 WB 冲刷同拍：仅 WB 生效；B 的纠正/更新必须已被 pipe_flush 屏蔽。
- 没有纠正且猜对：IF 指令可以照常送入 ID，包括实际发生跳转的情况。不得再用原始 actual_taken 屏蔽 fs_to_ds_valid。
- IF 空且没有特殊目标时，使用保存的后继游标；其复位值为启动地址。游标只在生成一个新取指项（RAM 请求或 ADEF 标记）时按该项预测后继前进，不能随表的实时变化漂移。
- 防御性处理：若待处理 WB 目标与 ID 纠正同时出现，WB 目标优先，测试应检查合法流水状态不会让旧 ID 指令越过这次 WB 清空。

### 5.3 逐拍例子

以下每行描述一个上升沿前的组合行为及该沿动作，假设无其他阻塞：

| 周期 | 情形与结果 |
|---|---|
| T0 | 请求地址 P，查到它预测跳到 Q；上升沿锁存 P 与预测 Q |
| T1 | RAM 返回 P 的指令，送入 ID；同时请求 Q，并锁存 Q 自己的预测 |
| T2，猜对 | ID 确认 P 的实际下一地址为 Q；Q 可送入 ID，不取消 |
| T2，猜错 | ID 确认 P 的实际下一地址为 R；Q 不送 ID，直接请求 R；P 正常进入 EXE |
| T3，猜错后 | RAM 返回 R，进入正确路径；Q 从未进入 EXE |

若 P 在 ID 等待寄存器数据，T2 延后：Q 留在 IF，预测信息一起保持，直到 P 真正发射才判断和训练。

### P2：联合正确性（C 组织，问题由模块负责人修复）

1. 接入真实 A/B/C 模块，无替代预测器；短程序覆盖循环、交替方向、连续分支、同索引冲突、目标变化。
2. 错误路径放写寄存器、写内存、CSR 写、syscall/break，证明它们不发生架构副作用。检查正确路径指令不丢失、不重复。
3. 与除法等待、load-use、异常/ERTN 冲刷交叉，验证不死锁及优先级。
4. 在 BP_ENABLE=0 和 1 下分别运行完整 ex9 课程镜像及参考写回轨迹；根据镜像实际覆盖列表补旧功能，勿无故重复全部历史镜像。
5. 不逐拍比较 rdcnt 读数等与运行时间相关的结果；性能不同导致计数值不同属正常，需按读数采样语义判断。若课程 golden 对此敏感，记录差异原因并采用能判定架构语义的用例，不能直接忽略失败。

### P3：性能与实现（C 采集，A/B 审核含义）

- 同一源码、镜像、复位方式、时钟与计时起止标志，分别关闭/开启预测；固定运行区间，覆盖分支密集循环及普通程序，不能只挑单一有利案例。
- 用 testbench/波形监测统计，第一版不新增软件可见 CSR：总运行周期、实际发射条件分支/无条件跳转数、分支纠正数、普通指令纠正数、分支 BTB 命中数。
- 分支下一地址准确率 = 1 − 分支纠正数/正常发射分支数；分母包含六种条件分支和 b/bl/jirl。分母为零报告 N/A。普通指令纠正另列，不能藏在分支准确率里。
- 周期改善 = (关闭周期−开启周期)/关闭周期；开启后更慢也如实记录。CPI 若报告，其分母用明确的提交指令计数，不能把发射数当提交数。
- 开启预测后重新综合/实现，记录 LUT/FF/BRAM、WNS/TNS/WHS/THS、未约束路径及构建配置；原 ex9 −2.931 ns 只是对照，不是本版本结果。
- 只有周期和可用时钟频率均有证据时，才比较实际执行时间；线上分数、周期降低、时序通过分别陈述。

## 8. 本次设计复核记录与边界

本次已人工对照固定基线 IF/ID 握手、BR 总线、异常优先级与全局冲刷连接，检查以下闭合关系：

| 设计风险 | 本规格的约束 |
|---|---|
