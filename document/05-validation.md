# 测试矩阵与交付门槛

所有条目都是**待执行**测试要求；本文件不是通过记录。测试目录和平台由负责人实施时创建，禁止把下面的案例ID写成现成脚本名。相同案例应有确定断言和超时，不能只看波形“像是对的”。

## 1. A：独立CSR测试

| ID | 激励 | 必须检查 |
|---|---|---|
| A01 | reset覆盖至少2拍 | CRMD=8，已约定清零的寄存器为0；ex9 TVAL=ffffffff |
| A02 | SAVE0旧值12345678；mask=00ff00ff，value=aabbccdd | 上升沿前读旧值，沿后读12bb56dd |
| A03 | CSR未知编号读写、只读位写、EENTRY低位写1 | 未知读0写忽略，只读位不改，EENTRY低6位仍0 |
| A04 | CSR写与wb_ex同拍；再做ERTN | 异常优先；ERA等取异常输入；ERTN恢复PLV/IE |
| A05 | SYS异常后检查CSR | Ecode=0b、EsubCode=0、ERA=原PC、PRMD为进入前状态 |
| A06 | ex9：仅一个IS位=1，切换LIE和IE | 只有状态和局部/全局使能都满足才有has_int |
| A07 | ex9：8路硬中断逐位、写软件中断 | 对应IS位正确；写软件位不抹掉硬件位 |
| A08 | ex9：TCFG初值4、单次/周期、初值0 | 逐拍对照04边界，单次停止，周期重装 |
| A09 | ex9：TICLR mask0、写0、写1，同拍到期 | 只有有效掩码写1清除；同拍到期置位优先 |
| A10 | ex9：暂停流水线、pipe_flush、稳定计数器低32位回绕 | 稳定计数器继续每拍+1；不同于TVAL；reset才清0 |
| A11 | ex9：BADV普通写、掩码写、掩码0 | 可完整读回；12345678经mask=00ff00ff、value=aabbccdd后为12bb56dd；掩码0保持 |
| A12 | ex9：BADV异常写与普通写竞争；再发生SYS等无错误地址异常 | 有效硬件错误地址优先；无地址异常保持；正常无事件保持；提交软件写时返回旧值 |
| A13 | ex9：仅写ECFG.LIE[12]，再写bit10/保留位 | bit12可读回1；bit10/保留位仍0；IS[12]=0故不触发中断 |
| A14 | 对照csr-registers-v1.json逐CSR检查权限 | RW掩码正确、只读状态不被普通写改动、TICLR写1行为；未知CSR的WR/XCHG给rd返回0 |

A08/A09补充边界：计数为0/1时关闭或重配置TCFG、同拍TICLR、重复关闭及重新启动；逐拍记录En、running、TVAL、IS[11]，按04/09区分团队约定和参考CPU实际行为。

A的测试平台直接驱动csr接口，无需等待B。重复reset、异常/返回事件优先级必须覆盖。测试输出至少为失败时打印案例ID/期望/实际，成功时汇总案例数量。

## 2. B：指令和流水线定向测试

| ID | 场景 | 必须检查 |
|---|---|---|
| B01 | CSRRD/CSRWR/CSRXCHG，rd非0与rd=0 | 写回旧CSR；CSR写入独立于rd=0；源寄存器/掩码正确 |
| B02 | 连续CSR写读、写写、写ERA后ERTN | 序列化后读新状态；没有重复提交 |
| B03 | CSR旧值立即用于ADD/分支/store | 真实WB结果；禁止EXE/MEM占位值前递 |
| B04 | syscall后紧跟store/普通写寄存器 | 处理程序运行，年轻副作用全被取消 |
| B05 | 强制构造MEM较老异常、EXE年轻store | **WB报出前一拍**也禁止data_sram_en及we |
| B06 | WB冲刷同拍EXE除法等待/ID RAW阻塞 | valid仍清零，不能等待allowin或done |
| B07 | 除法发出后冲刷，再立即准备新有符号/无符号除法 | IP复位2拍+恢复1拍，新请求只发一次；超过旧延迟36拍仍无旧结果污染 |
| B08 | 连续两次冲刷、IP恢复期再冲刷 | 重启恢复计时，无请求丢失或误领结果 |
| B09 | 164位每字段不同图样，阻塞/气泡/冲刷 | 数据和元数据不串指令；字段顺序正确 |
| B10 | ex9：BRK、INE、各类ALE | ecode、ERA、BADV正确；错误读写请求为0 |
| B11 | ex9：中断覆盖正常指令；has_int在ID阻塞时改变 | 仅实际发射时锁存；原指令副作用取消；提交一次 |
| B12 | ex9：LOW/HIGH/ID及立即依赖 | 目的字段正确；LOW/HIGH采样EXE传输前值，阻塞后保持 |

EXE/MEM状态的特殊交叉场景可用模块测试直接注入合法状态；测试中说明“模块激励”，不要声称课程程序必然自然触发。替代CSR只用于早期连线自测，最后B01～B04必须连真实A模块。

## 5. 课程镜像及参考轨迹

1. 用课程for_test_obj/ex8_obj或ex9_obj的六个文件替换本机func/obj，保存SHA-256；对应哈希见baseline.json。
2. 重新生成相关RAM IP的Output Products，关闭旧仿真；避免加载之前ex7镜像。
3. 参考工程先生成同一镜像的golden_trace，再用CPU工程比对。绝不沿用ex7轨迹验证ex8。
4. baseline.json中的47/58是反汇编测试标签的静态清点，不是本次运行到该编号的证据；最终还需核对入口实际调用及完整结束日志。
5. 本地CPU结束应出现Test end和最终PASS，参考结束应出现Succeed in generating trace file。记录完整时间与文件，partial.log不能冒充完整日志。
6. 软件中断和定时器测试不代替8路外部硬中断测试。课程测试未覆盖的条目补单独断言。

所有测试需配置有界超时。测试CSR/短程序建议从微秒级开始，完整func按基线和实际日志设置并记录上限；超时先保留PC、valid、done、flush现场，不能无限等。
