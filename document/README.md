## 已固定的技术决策

1. CSR 在 WB 组合读出，在 WB 提交的上升沿写入；普通指令仍沿用五级流水线。
2. 异常随指令传递，到 WB 提交；`ertn` 也到 WB 生效。CSR 旧值才是 CSR 指令的通用寄存器写回值。
3. 原 ex7 数据总线顺序、宽度不变。增加并行的 164 位元数据总线；IF 增加 49 位异常信息总线。
4. CSR / syscall / ertn 使用保守的流水线序列化，优先保证正确性。不得由某个 AI 单独改成 CSR 前递。
5. 全局冲刷优先于 allowin / 多周期等待。数据请求在组合逻辑中提前屏蔽，不能只靠清 valid。
6. 除法取消采用两个 IP 一起复位并等待恢复的策略，不采用仅清包装器状态的策略。
7. ex9 接口从 ex8 起预留，ex8 时计数器操作、中断和扩展异常字段按规范置零。

## 使用方法

每人取得同一份完整仓库和课程资料，把本目录及本人任务书交给 AI，并让 AI 实际读取本地 CPU 文件。只粘贴任务书而没有代码，不能让 AI 假设端口已存在。

三人先共同读 02、03，按 05 的里程碑推进。C 先提交“接口骨架”的整合提交：端口与总线能够连接、所有新增功能保持关闭。A/B/C 再从这个共同提交并行开发。

**本资料包不需要队友重新选择架构方案。** 实施中发现与课程手册或测试确实冲突时，按 01 的接口变更流程修订；不能悄悄换端口、位宽或时序。
