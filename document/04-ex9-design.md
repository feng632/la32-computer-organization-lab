# ex9 增量设计与已预留接口

在ex8真实模块和完整测试通过的提交上实施，不在三条分支分别复制不同的ex8版本。仍使用TEAM-ABI-1.0；总线不再扩宽。

## 1. 异常检测、编码和地址

| 异常 | 检测责任人/级 | Ecode | EsubCode | badv_valid / badv |
|---|---|---:|---:|---|
| INT | A产生has_int，B在ID标记 | 0x00 | 0 | 0 / 0 |
| ADEF | C，IF请求前 | 0x08 | 0 | 1 / 错误PC |
| ALE | B，EXE有效地址形成后 | 0x09 | 0 | 1 / 完整有效地址 |
| SYS | B，ID | 0x0b | 0 | 0 / 0 |
| BRK | B，ID | 0x0c | 0 | 0 / 0 |
| INE | B，ID | 0x0d | 0 | 0 / 0 |

课程本次ADEF检查PC[1:0]!=0；不扩展到MMU或其他地址权限异常。IF发现错误地址时不发RAM请求，构造`inst=0, pc=错误地址, fs_to_ds_ex=ADEF`的有效异常标记，正常送ID。ID看到取指异常不能再将inst=0译成INE。

ALE：ld.h/ld.hu/st.h检查地址bit0；ld.w/st.w检查低两位；字节访问不要求对齐。先形成ALE再组合禁止EXE请求，不能先写后报错。

同一指令优先级固定为：INT > IF已有ADEF > ID的INE/SYS/BRK > EXE的ALE。ID检测项正常情况下互斥；已有高优先级异常沿途保留，不被后级覆盖。不同指令按年龄顺序提交，不能让年轻指令的高编码优先级越过较老指令。

has_int只在ID具备发射条件、旧CSR/返回影响已清除时采样，异常信息锁存在本次传输中；阻塞期间不重复提交。已经锁存的INT不因之后has_int撤销而取消。INT标记取消原指令所有副作用，ERA指向原指令，返回后可重新执行原指令。

## 2. ex9 CSR增量

| 名称 | 编号 | 实现与可写范围 | 团队复位 |
|---|---|---|---|
| ECFG | 0x004 | LIE[12:11]、LIE[9:0]可读写；bit10及[31:13]恒0；软件可写掩码0x00001bff | 0 |
| ESTAT增量 | 0x005 | IS[9:2]采样8个硬中断；IS[11]定时器；IS[10]、IS[12]固定0 | 软件/定时中断0 |
| BADV | 0x007 | 32位可读写，支持CSRWR/CSRXCHG掩码写；wb_ex且wb_badv_valid时由硬件记录错误地址，硬件更新优先 | 0 |
| TID | 0x040 | 32位软件可写 | 0 |
| TCFG | 0x041 | En[0]、Periodic[1]、InitVal[31:2]软件可写 | 0 |
| TVAL | 0x042 | 32位倒计时只读 | 0xffffffff |
| TICLR | 0x044 | 读零；有效掩码写bit0=1清定时中断 | 0 |

has_int固定为CRMD.IE与ESTAT.IS/ECFG.LIE的相应实现位共同判断；不考虑核间中断，不做向量入口，ex_entry仍只取EENTRY。

不实现核间中断时，ESTAT.IS[12]固定0，ECFG.LIE[12]仍保留软件可读写行为。未连接中断源与删除控制位读写能力不是一回事；LIE[12]=1也不会凭空触发中断。

BADV更新优先级：reset清0；`wb_ex && wb_badv_valid`写入wb_badv；否则合格的普通CSR写BADV按掩码更新；其余保持。SYS/BRK/INE/INT等不提供错误地址的异常不清BADV。普通CSR写由02的csr_we资格条件保证与异常/ERTN互斥，不能把该寄存器“可由硬件更新”理解为“软件只读”。

硬中断来自同步hw_int_in，按时钟采样；软件中断仅ESTAT[1:0]由CSR写改变；定时中断独立保持到清除。不同位分别更新，不能因写软件位覆盖同拍硬件状态。

## 3. 定时器的周期语义

采用32位timer_count与内部timer_running。TCFG.En是软件配置位，单次到期后停止计数，不擅自把软件可见En清零。

- 合格写TCFG时，先按掩码得到new_tcfg。new.En=1：装载`{new.InitVal,2'b00}`并启动；new.En=0：停止，计数值保持。写TCFG不隐式清已挂起中断。
- 无重配置时，running且计数>0，每拍减1；当周期开始时计数已为0，则本拍事件到期：置ESTAT.IS[11]。周期模式装载初值继续；单次模式停止并将TVAL置0xffffffff。
- 例如初值4：装载后的周期依次可观察4、3、2、1、0，随后上升沿置中断并重装或停止。初值0在装载后下一个上升沿到期。
- 定时中断到期置位优先于同拍TICLR清除；下一次合格清除才能清零。复位优先级最高。
- 同拍TCFG重配置优先于旧计数的递减/重装；旧计数已为0且running的到期事件仍可置中断。每个状态字段单独列优先级，不用一个大if阻止无关字段更新。

以上定时边界采用课程指导书timer_cnt==0的时序思路。若课程提供的参考CPU在边界上出现可复现差异，必须三方同步修订规范及测试，不能各自采用不同计数边界。

## 4. 稳定计数器与读取指令

A在csr内维护64位稳定计数器：reset清0，非reset每拍+1，溢出自然回绕；不受阻塞、pipe_flush、TCFG写入影响。与TVAL倒计时是两个状态对象。

B译码三条课程指令，必须核对课程LA32R编码和汇编展开。`rdcntvl.w`/`rdcntvh.w`目的为rd，`rdcntid`的目标字段为rj，不能照搬普通rd路径；后者别名形式需按课程反汇编检查。

LOW/HIGH在EXE向MEM实际传输时采样counter_value对应32位，通过cnt_value送WB；ID操作在WB用tid_value写回。三者不访问数据RAM、不写CSR。三条计数器读取都作为序列化操作，排空较老指令并阻止年轻指令越过，避免与TID更新及写回结果发生冲突。

计数器最终值在WB选择，EXE/MEM的计数器指令对ID屏蔽普通ALU前递gr_we；年轻指令由序列化等待，WB前递真实结果。此规则与保守CSR处理一致，禁止将地址或ALU占位值前递。

02中的`*_serializing`从接口骨架开始就包含cnt_op!=NONE；ID对这三条指令使用03的older_valid排空规则。ex8不译码这些指令，cnt_op恒NONE。

## 5. ex9交付次序

A/B/C先接通BADV与ADEF/ALE/INE/BRK，再接软件中断与硬件中断，再接定时器与计数器读取。每项先运行05对应定向测试；最后课程ex9镜像完整验证。改变对外顶层端口后必须修齐原有SoC及测试例化，不能靠悬空输入“看起来不触发”。
